# gfx studio — Tauri IPC API (frontend)

`withGlobalTauri: true`, so use `const { invoke } = window.__TAURI__.core;` (no npm package needed).
Detect Tauri with `!!window.__TAURI__`. Arg names are camelCase per Tauri v2 (`rel`, `text`, `path` are single words, so identical).
All `rel` paths: relative to project root, forward slashes, no leading `/`, no `..`, no drive letters (else the promise rejects with a string error).

## Settings, welcome window (docs/HOME-SETTINGS.md, `src/prefs.rs`, `src/welcome.rs`)
- **Machine settings** (`settings.json`): `shell`, `claudeCommand` (always present, `''` = default) plus, only when set: `onStart` (`welcome` \| `last`),
  `projectsDir` (absolute path), `editor` (`vscode` \| `system` \| `custom`), `editorCommand`, `uiZoom` (a UI scale step), `showHeaders`, `renderMode`
  (`fast` \| `exact`), `renderWorkers` (0 = auto, 1-16), `renderPreset` (`scene` or a preset id), `renderQuality` (`draft` \| `normal` \| `high`),
  `renderFrameFormat` (`png` \| `jpeg`), `renderAudio`, `renderOutDir` (`out` or a folder in it), `codeAutosave`, `versionsAuto`,
  `askSend`, `engineDir`, `workflow` (`quick` \| `full` \| `{ verify: sheet|stills|full, render: bool, sound: asked|always }`, docs/LOOKS.md §1),
  `libraryDir` (absolute path; default `<Documents>/gfx library` in `settings_meta().defaults.libraryDir`). Validation: `prefs::check_pref` (twin
  `web/src/settings-core.js#checkPref`). The page stores "not set" instead of a value equal to the default.
- **Project overrides** (`gfx.json` → `"settings"`): only `render*`, `codeAutosave`, `versionsAuto`, `workflow`. Resolution: project → this computer → built-in default.
- **Workflow → CLAUDE.md**: `await invoke('refresh_workflow_block')` → `bool` (false = nothing to refresh: no gfx.json, or an engine checkout); runs
  `gfx init --refresh --no-skills --workflow <machine default>` in the open project (`prefs::workflow_arg`: the name, or the custom object as JSON),
  rejects with the engine's last stderr line. `prefs.js` calls it after every `workflow` change. `project_opened` also refreshes when
  `.gfx/workflow.json` `machine` differs from the machine setting, and always passes `--workflow`.
- **Windows**: `welcome` (`welcome.html`, 960×620, min 760×520, `disable_drag_drop_handler`, capability `capabilities/welcome.json`) is the only window at
  start unless `onStart` = `last` and the root is still a project (then the main window). The main window is built on demand by `popout::build_main`
  (the pop-out new-window handler); closing the welcome window while no main window is open quits the app; closing the main window still closes the
  pop-outs. Events to the main window: `gfx://open-project` (path), `gfx://open-settings` (page id). Folder drop: the welcome page posts the dropped
  `File`s with `chrome.webview.postMessageWithAdditionalObjects('gfx-drop', files)`; `welcome.rs` reads `ICoreWebView2File::Path` (webview2-com) and
  emits `gfx://dropped` (paths) to the welcome window.
- **Dev shim**: the same ops in `vite.config.js` (files: `GFX_STUDIO_SETTINGS`, recent.json next to it or `GFX_STUDIO_RECENT`); the welcome window is the
  page `welcome.html`; `welcome_open` sets the root and the page loads `index.html`; `pick_folder` is a `window.prompt` in the browser.

## `gfxlib://` read-only library scheme
Custom URI scheme (`register_asynchronous_uri_scheme_protocol`, file read on a worker thread). URL: `gfxlib://localhost/f/<percent-encoded path>`; on Windows/Android WebViews it is `http://gfxlib.localhost/f/...` (use `api.libUrl(path)`, which picks the right one; the dev shim serves the same at `/__lib/f/...`). Responses carry `Access-Control-Allow-Origin: *` (page origin differs); no Range support. `GET` only (OPTIONS answers 204).
Served (`resolve_lib_in`): (a) `library/<...>` (or `<library folder name>/<...>`) = model / index / audio files (`.onnx .json .jsonl .txt` + audio) in the **engine's sound library**, (b) `.gfx/index/<id>.jsonl|.meta.json` = the index of a project source (an `id` in the project's `gfx.json` `library.sources[]`), (c) audio files (`.wav .ogg .mp3 .flac .aif .aiff .m4a .opus`) inside the `path` of a registered folder source: `sources.json` (relative to the library's parent, or absolute) or gfx.json `library.sources[]` (relative to the project, or absolute); a relative request is tried under the library's parent, then under the project; an absolute one is compared in the engine's spelling (`D:/x` and `/mnt/d/x` are the same place, case-insensitive; a gfx.json relative source as `<project as the engine sees it>/<path>`). Anything else is 403 (`..`, other roots, non-audio outside the library, other project areas, `..` in a source path), missing files 404. Content-Type: `.onnx` application/octet-stream, `.json` application/json, `.jsonl/.txt` text/plain, `.wav` audio/wav, `.ogg` audio/ogg, `.mp3` audio/mpeg, `.flac` audio/flac. Guard unit-tested (`cargo test --lib`: gfxlib_*), twin in `web/lib-guard.js` for the dev shim.
**Where the library is** (`LibScope`): the engine is asked, not guessed: `gfx lib list --json` → `library` (GFX_LIBRARY, else `<engine>/library`, else the per-user data dir) through the project's engine (`spec_for`: a WSL project's engine, else the located engine). The path becomes readable for the app (`readable_abs`): a WSL engine's `/home/...` → `\\wsl.localhost\<distro>\home\...`, `/mnt/d/...` → `D:/...`; a Windows engine's path as is. Cached in `AppState.lib` per project root: the first gfxlib request after a project switch asks the engine (one at a time; `set_root` clears it), a failure (no engine yet) falls back to `<root>/library` (the old behaviour). `invoke('lib_locate')` (`api.libLocate()`) asks again -> `{ library: <engine path> | null, dir: <readable dir> | null, error? }`; soundindex.js calls it before reading sources.json after a project switch, an Engine folder change, or a Sound sources add / toggle / remove. Dev shim: the `lib_locate` op and `/__lib/f` run `node <engine>/runner/cli.js lib list --json` in the project the same way.

## Live server (`start_server`)
`api.serverStatus()` is a webview `fetch` of `http://127.0.0.1:5199/__gfx/ping` (600 ms timeout; the ping sends CORS `*`) -> `{ url | null }`; `api.startServer()` invokes `start_server`. Rust: `wsl_target(root)` (pure, unit-tested) derives distro + Linux path from `\\wsl.localhost\<distro>\...` / `\\wsl$\<distro>\...` (also the `\\?\UNC\` form; a plain Linux path is accepted when not on Windows; anything else errors). On Windows it spawns `serve --port 5199` through the Engine runner below (a WSL project: `wsl.exe -d <distro> --cd <path> -- bash -lc "GFX_PROJECT=<path> node '<engine>/runner/cli.js' 'serve' '--port' '5199'"`) with `CREATE_NO_WINDOW`, keeps the `Child` in `AppState`, kills it on `RunEvent::Exit` and when the root changes (`set_root` / `pick_root`). The dev shim (`vite.config.js`) spawns `node runner/cli.js serve --port 5199` locally (detached from nothing: killed when the Vite server closes). Needs capability `allow-start-server` (added).

## Engine runner (`engine_run` / `engine_cancel`)
`opts`: `{ progress?: bool (append --progress json), noProject?: bool (init/doctor/setup: no GFX_PROJECT, cwd = engine), env?: { GFX_*: string } }`. `jobId`: `[A-Za-z0-9_-]{1,64}` (`serve` reserved). Native project: `<engine>/node/node.exe <engine>/runner/cli.js <args>` with env `GFX_PROJECT=<root>` and cwd = root (engine dir = `GFX_ENGINE`, else the Engine folder setting `engineDir`, else `engine/` next to the exe; node = `GFX_NODE`, else the bundled `node.exe`, else `node` on PATH for dev engines). **WSL engine** (`engineDir` = `\\wsl.localhost\<distro>\...` or `\\wsl$\...`): every command runs through `wsl.exe -d <distro> --cd <cwd> -- bash -lc "[GFX_*=..] node <cli.js> '<arg>'..."`; no project (`init`, `doctor`, `setup`): cwd = the engine's Linux path and `runner/cli.js`; a native project: cwd = its `/mnt/<drive>/...` path, `GFX_PROJECT=/mnt/...`, the engine's `cli.js` by its Linux path. Windows path arguments (`gfx init C:\...`) become `/mnt/c/...`; outputs come back as `/mnt/...` paths (the frontend uses the `out/...` part). The live server's ping root `/mnt/c/x` matches the project `C:\x`. **WSL project** (`\\wsl.localhost\<distro>\...`, `wsl_root_engine` / pure `wsl_project_engine`): a project that is itself an engine checkout (has `runner/cli.js`, this repo) runs its own `cli.js`; any other runs the located engine, which must be a WSL engine in the same distro: `wsl.exe -d <distro> --cd <project linux path> -- bash -lc "[GFX_*=..] GFX_PROJECT=<project linux path> node '<engine linux path>/runner/cli.js' '<arg>'..."` (`build_wsl_engine_command`). A Windows engine (its Vite answers 404 for scene files under a `\\wsl.localhost` root) or an engine in another distro is refused with a message naming the fix (an Engine folder inside that distro). stdout lines are parsed as JSON events (`progress`/`log`/`done`/`error`), other stdout lines become `{type:'log',level:'info',stream:'stdout'}`, stderr lines `{type:'log',level:'warn',stream:'stderr'}`; all are emitted as Tauri events `engine://<jobId>`, followed by `{type:'exit',code,canceled}`. `outputs` = the `done` event's outputs. Cancel: `taskkill.exe /PID n /T /F` (Windows) / process-group kill (Unix). Project opened (`set_root` / `pick_root` / welcome open / start with Reopen last project, `project_opened`, on a thread; engine checkouts are skipped): `.gfx/engine.json` is written when missing or naming another engine (`engine_record`: a WSL engine gives Linux paths, plus `wsl: <distro>` for a Windows-folder project; a native engine gives its folder, `bin\gfx.cmd` and node), `.gfx/` is appended to `.gitignore` when no line covers it, and when the CLAUDE.md managed block differs from the engine's `templates/projects/_shared/CLAUDE.md` (`managed_block_outdated`) the engine runs `gfx init --refresh --no-skills`; when the engine's skills changed since the project's `.gfx/skills.json` (`skills_outdated`: `skills_hash` of `<engine>/.claude/skills` ≠ its `engineHash`, or no record) it runs `gfx init --refresh` instead (block + non-destructive skill sync, `refresh_args`). `start_server` is `engine_run` of `serve --port 5199` under the reserved id `serve` (reused when the ping root matches; killed on project switch/exit). Frontend: `api.engineRun(args, { onEvent, progress, noProject, env }) -> { jobId, done }`, `api.engineCancel(jobId)`. Dev shim: `engine_run` starts a child (`node <engine>/runner/cli.js`, cwd = project), events come from `GET ./__api/engine_events?job=<id>` (Server-Sent Events, replayed from the start, ends after `exit`).

## Terminals (`pty_*`, docs/CLAUDE-IN-APP.md §3)
portable-pty (ConPTY on Windows). Shell: WSL root -> `wsl.exe -d <distro> --cd <path> -- bash -lc 'export PATH=<engine>/bin:"$PATH" GFX_PROJECT=<path> GFX_ENGINE=<engine>; exec bash -l'` (`<engine>` = the engine's Linux path from `wsl_root_engine`, as for `engine_run`; the project itself when it is the engine or no engine fits); native root -> the `shell` setting (command line, double quotes allowed), else `pwsh.exe -NoLogo` when on PATH, else `powershell.exe -NoLogo`; cwd = project, `PATH` = `<engine>/bin;<PATH>`, `GFX_PROJECT`, `GFX_ENGINE` (pure `claude::shell_spec`, unit-tested). Output is read on a thread and emitted as `pty://<id>` events `{ data }` batched every ~16 ms (UTF-8 sequences never split), then `{ exit: code|null }`. ConPTY asks for the cursor position (`ESC[6n`) at start and waits: xterm.js answers it, so the frontend queues input until `pty_open` returns instead of dropping it. Terminals are closed on project switch (`set_root`/`pick_root`), on app exit, and by the frontend after a webview reload (`pty_close('*')`). Dev shim: python `pty` helper (resize over fd 3), output as SSE `GET ./__api/pty_events?id=`, settings in `$GFX_STUDIO_SETTINGS` or `<tmp>/gfx-studio-dev-settings.json`. Capabilities: `allow-pty-*`, `allow-get-settings`, `allow-set-settings`, `allow-open-link`, `allow-list-project-files`, `allow-write-project-file`.

## T3 Code (`t3_*`, docs/T3.md, `src/t3.rs`)
Secrets (access token, signed client id) live only in `<app config dir>/t3.json`; no command returns them, nothing logs them. OAuth: `GET <server>/.well-known/oauth-authorization-server` (issuer must equal the server, every endpoint on it, S256), `POST /oauth/mcp/register` once per server and level (`client_name` "gfx studio · Full" / "· Standard" / "· Read only", the label of the grant in T3 → Settings → Connections; redirect `http://127.0.0.1/gfx-studio/callback`, the port is ignored by T3), PKCE S256 with `resource=<server>/mcp` and scope `orchestration:read orchestration:operate`, approved by gfx itself with a pairing code: `POST /oauth/mcp/decision { authorization, decision: { _tag: "pairing-code", access, code } }` → `{ redirectTo }` (state + `iss` checked; nothing listens on the redirect URI), form POST to `/oauth/mcp/token`; the level comes from the granted scopes (`settings:write` = full, `orchestration:operate` = standard, else read-only). MCP: streamable HTTP `POST <server>/mcp` with Bearer, `initialize` (+ `notifications/initialized`) once per token, `Mcp-Session-Id` kept, a 404 re-initializes once, JSON or SSE answers (last matching `message` event), 401/403 → token forgotten + reconnect. Allowlist: read `t3_environment_read t3_project_list t3_thread_list t3_thread_read t3_thread_wait`; standard+ `t3_thread_launch t3_thread_send t3_attachment_prepare_upload t3_thread_send_attachments`; full `t3_project_create`; nothing else (no delete / archive / settle / interrupt). T3 view: `Window::add_child` (Tauri `unstable`) labelled `t3view`, `disable_drag_drop_handler`, navigation limited to the server (other links open outside), new windows denied; `close_popout` and a pop-out's native close move it back to `main` hidden first (`rescue_view`). Dev shim twin: `web/t3-shim.js` (config `$GFX_STUDIO_T3` or `<tmp>/gfx-studio-dev-t3.json`; no view; `GFX_T3_SHIM_APPROVE=1` emulates the view's cookie jar for the mock). Capabilities: `allow-t3-*`.

## Dock pop-out windows + UI zoom (docs/LAYOUT.md §4, §5)
The main window is built in `setup()` (`popout::build_main`; `tauri.conf.json` has `"create": false` for `main`) with `WebviewWindowBuilder::on_new_window`: a `window.open` of our own `popout.html` (`tauri://localhost` or `http(s)://tauri.localhost`, pure `popout::is_popout_url`, unit-tested) gets a new Tauri window labelled `popout-<n>` returned as `NewWindowResponse::Create` (dockview then moves panel elements into it; `Allow` hangs dockview); any other URL is denied. `close_popout(label)` closes a `popout-*` window (dockview calls `window.close()` from the opener, which does not destroy a Tauri-created window). Whole-UI zoom is the JS API `getCurrentWebview().setZoom(f)` (+ `getAllWebviews()` for open pop-outs). Capabilities: `allow-close-popout`, `core:webview:allow-set-webview-zoom`, `core:webview:allow-get-all-webviews`.
